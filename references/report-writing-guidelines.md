## 自包含原则

写作前判定主论文类型。方法与实证论文以实验、对照和统计为主要证据；理论论文以假设、定理、证明依赖和反例为主要证据；系统、平台、数据集与 benchmark 以接口、协议、覆盖、泄漏、系统测试和失败案例为主要证据；单篇综述或观点论文以范围、纳入标准、材料覆盖、综合或论证链为主要证据。论文可有必要的次类型。不要为固定章节凑实验、公式、图片或外部文献。

唯一交付主体是 `output/{arxiv_id}_{title}/{arxiv_id}_阅读报告.md`。以下内容必须写进主报告：

- arXiv、hjfy、papers.cool 链接
- 核心主张及证据强度
- 主结果、关键消融和实验—主张矩阵
- 相关论文表与实际引用的外部文献
- 关键图片、公式及其就地解释
- 复现风险与代码—论文不一致

缓存 JSON 是证据索引，不能替代正文。

4.5 相关论文表只写论文标题、基础 arXiv ID、作者/年份、来源/类型、关系和概述，不添加网络链接。Obsidian 双链由同步器根据 vault 缓存索引自动注入；未命中时保持纯文本。外部文献的核查链接放附录 B，主论文的 PDF 定位链接放在对应论证处。

## 第一性原理速览

在 abstract callout 后、原第 1 章前放置 `## 0. 第一性原理论文速览`。先完成证据账本和深度分析，再回写速览；不要把速览当作预读摘要。完整六问、推理纪律和格式读取 [first-principles-quicklook.md](first-principles-quicklook.md)。

速览先给读者研究对象、核心思路、最重要结论及决定性证据，再给边界与判断。正文先建立术语和机制，再审查 Claim。附录保留审计需要的完整证据与细节；同一论点只完整解释一次，其余位置引用主张 ID。

## 研究逻辑链

每份报告在 §1.1 背景与动机之后加入 schema 指定的研究逻辑链小节，先解释各部分为什么相连，再进入问题细节和公式。按 [research-logic-chain.md](research-logic-chain.md) 写一段可独立理解的主线；存在重要分支时加 Mermaid 图，复杂论证再加阶段表。Motivation 说明为什么研究，Insight / Novelty 说明发现和设计，逻辑链说明它们如何连接，主张表记录具体证据强度；同一论点不在四处完整复述。

方法和证据章节用过渡句指出当前在解释、检验主线中的哪一步。对照表可增加“研究阶段 / 验证对象”列，区分前提、模型、模块、机制与完整系统效果，避免把某一层验证替代另一层。不要为凑图而虚构步骤，或把所有论文强排成同一条实验流水线。

## 证据与语言

- 区分作者显式主张、隐含主张和 reviewer 推断。
- 每个重要判断绑定原文位置、公式、图表或外部文献。
- 证据不能闭环时直接写“证据链未闭环”。
- 不用“一定、证明了、完全解决”等超过证据强度的措辞。
- 内联枚举改成有序列表，每项用粗体关键词开头。

## 原文证据

每条核心主张在深读正文第 1–6 章的对应论证旁展示原文依据。速览和其他重复位置可以用主张 ID 回指。

- 作者措辞影响判断时，短引原文中决定含义的连续片段，保留条件、范围和限定词。优先核对作者明示的动机、贡献、假设、适用范围、局限和有争议的表述。把中文释义和 reviewer 推断写在引用之后。
- 对实验结果给出原表行列或子图、指标、关键数值和对照条件。对理论结论给出原公式、定理及关键假设。定义、协议或数据覆盖同样定位到对应段落或附录。原文只提供间接证据时，说明这处证据支持的范围与缺口。
- 一条主张需要多处原文才能成立时，分别记录。直接引用随论证需要选择，图表、公式和定义同样计入原文证据覆盖。

### 账本与正文

新工作区使用 `cache/claims.json` 的 `2.0` 格式。顶层 `paper_source` 记录 `version`（读者可辨认的版本名）、`pdf_path`（工作区内 `raw/` 下的实际文件）和 `pdf_url`（同版 PDF 地址，私有稿可留空）。默认使用流水线下载的版本化 arXiv PDF。采用用户提供的会议稿时，保留为 `raw/` 下的独立文件，并把三项改成会议稿来源。

每条 `claims` 记录用 `citations` 代替旧 `paper_location`。每个引用包含从 1 起算的 PDF 物理页 `page` 和精确位置 `locator`，例如 `§5.1 末段`、`表 2，Full 行 × Success 列` 或 `式 (4)`。直接引用时另填 `quote`，原样录入连续片段并折成一行。遇到扫描页或文字层错序时，人工读图核对后用注明位置的转述。用 `evidence` 记录关键数据、前提或证明步骤及其对主张的支撑。保留既有 `claim_kind`、`evidence_strength` 和 `reviewer_conclusion` 字段。

1.3 主张表的「主张内容」填账本中的 `claim`，「原文位置」填首条引用的位置链接。正文把每条引用写成独立一行，紧接中文释义、关键数据或 reviewer 判断。以下为格式示例。

```markdown
> **原文依据（C1）** [arXiv 2401.12345v1 · PDF 第 6 页 · §5.1 末段](https://arxiv.org/pdf/2401.12345v1.pdf#page=6) · “The estimator assumes uniform sampling.”
```

无逐字摘录时，引用行写到位置链接为止。私有 PDF 用相同的版本、页码和位置文字，省略链接。核对 PDF 页、短引和表格数值后，再说明证据支持了什么。自动验收核对主张 ID、位置、正文引用和逐字摘录，图表数值、公式与论证含义由撰写者核对。

## 图片与表格

图片优先使用作者源码原图并与 PDF 核对，其次 PDF 嵌入图、figure 裁剪和整页 fallback。禁止网页截图。

图片按论证位置插入：任务图放 1.2，方法图放 2.3，结果图放 3.3，失败/消融图放 3.4 或对应质疑附近。每张图后解释展示内容、与主张的关系和证据边界。

正文分析依赖的关键表必须就地转写；附录只补完整列。不要只用“优于 baseline”代替数值。

第 3 章保留既有标题以兼容已有报告，但对非实验论文应改写为相应的“主张—证据”分析。3.3 没有实验结果时删除占位表行，写“实验结果不适用/原文未提供”、原因、实际采用的证据以及这对结论强度的影响。4.5 没有可靠相关论文时同样删除占位行，写明检索范围、未检索到可靠文献的原因及影响。附录 B 未使用外部文献时明确说明，不留空白占位。原文无关键图片时可以不插图。

## 数学与代码

- `## 0. 第一性原理论文速览` 不使用任何形式的 LaTeX，公式仅用纯文本表达。
- 行内数学使用 `$...$`，display 使用 `$$...$$`。
- 多行使用标准 LaTeX 环境。
- 需要引用的公式在块内用连续 `\tag{N}`。 tag必须位于内部对齐环境的 `\end{...}` 之后、外层 `$$` 之前。
- 数学不用反引号；函数、类、配置键和真代码使用反引号。
- 公式解释包含自然语言、符号、工程映射、假设和必要的 toy example。

含公式时另读 [MathJax渲染验证](mathjax-validation.md)：静态验收与实际逐式渲染分开记录，不用编号连续或当前可见DOM无错误替代全文引擎验证。

## Obsidian Markdown

- 以 YAML frontmatter 开头，不含 `one_liner`。
- 不使用 H1；frontmatter 后立即写 `[!abstract]` callout。
- 默认图片语法为 `![alt](images/...)`。
- 外部 URL 用标准 Markdown 链接；只有 vault 内部笔记使用 wikilink。
- callout 用于摘要、关键结论、质疑和边界，每小节通常避免超过 2–3 个；速览的 Insight / Novelty 按实际条目数逐条使用纵向 callout，不为数量限制合并不同观点。字段、编号与示例见 [first-principles-quicklook.md](first-principles-quicklook.md)。
- 最终报告不得残留 TODO、隐藏调试注释或占位符。
