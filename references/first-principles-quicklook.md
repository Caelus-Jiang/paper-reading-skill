# 第一性原理论文速览

以第一性原理思考者的角色，从基本原理和常识出发推演论文的做事思路。把速览放在摘要之后、既有深度报告之前，但在完成原文阅读、主张—证据账本和 reviewer-level 分析之后再写。速览是深度分析的压缩索引，不是只读摘要后形成的预判。

## 推理纪律

- 从任务的对象、可观测信息、可控变量、目标、约束和最小必要假设出发，先去掉论文术语，再重建论文方案。
- 将 `Inspiration`、`Insight` 与 `Novelty` 分开：Inspiration 是触发洞见的既有事实、失败现象、理论或相关工作；Insight 是作者对问题结构或解法结构的判断；Novelty 是为落实 Insight 而新增的架构、方法或策略。
- 优先使用作者明确给出的动机链。作者未明确说明时，标记为 `reviewer 推断`，并给出原文依据；不得把事后合理化写成作者的真实思路。
- 每个重要判断绑定论文位置、公式、图表或实验。无法确认时直接写“原文未明确说明”或“证据链未闭环”。
- 省略客套话、背景铺陈和重复摘要，直接回答六问。

## 六问结构

### 1. Task

尽可能形式化地说明问题。至少回答：输入与已知信息是什么、输出或决策是什么、优化目标或成功标准是什么、有哪些约束与假设、训练与推理阶段分别可访问什么。若论文适合写成优化问题，使用纯文本表达，例如“在约束 C 下，选择策略 pi，使期望任务损失最小”。

### 2. Challenge

说明传统方法为何在该问题上失败，不只列举缺点。把困难还原到信息不足、优化困难、计算或存储成本、数据分布、信用分配、泛化、系统约束等基本原因，并指出论文用什么证据证明这些挑战确实存在。

### 3. Insight

每条使用一个原生 `[!tip]` callout，以稳定编号 I1、I2…及可独立理解的结论短标题开头。先给洞见，再解释触发它的 Inspiration；多个观察可合并支撑同一洞见。字段逐行写，依据收尾：

```markdown
> [!tip] I1｜保留状态可以缓解历史信息丢失
>
> **核心洞见**：决策需要的历史信息可压缩到持续更新的状态中。
>
> **触发观察**：仅依赖当前输入时，早期线索在后续决策中不可访问。
>
> **洞见类型**：信息结构 / 架构。
>
> **依据**：§2 的问题设定；上述动机链为 reviewer 推断。
```

`核心洞见` 写判断，`触发观察` 写既有事实、失败现象、理论或相关工作，不要互相复述。`洞见类型` 标明问题表示、信息结构、目标函数、优化、架构、训练、推理或数据策略等类别。作者未明说的推理须在相关字段标为 `reviewer 推断`，并附原文依据。

### 4. Novelty

每条使用一个原生 `[!example]` callout，以 N1、N2…及具体设计短标题开头。按“问题—关联洞见—具体设计”纵向呈现，不用长括号箭头链：

```markdown
> [!example] N1｜增加跨步骤更新的循环状态模块
>
> **解决问题**：当前输入不足以恢复早期线索。
>
> **对应洞见**：I1——压缩并保留决策所需的历史信息。
>
> **具体设计**：引入跨步骤传递的状态，并用当前观测更新状态后再生成决策。
>
> **创新归类**：架构 / 已有组件重组，独立创新程度仍需文献对照。
>
> **依据**：§3 方法定义；效果需结合 §4 的状态模块消融判断。
```

`对应洞见` 必须引用本节存在的 I 编号并附简短解释，允许一对多和多对一，不重复整个 Insight。`具体设计` 说明实际新增或改变的机制。`创新归类` 区分架构、方法、目标、训练策略、推理策略、数据策略、系统实现或已有组件重组。`依据` 集中放原文位置、必要的结果数值和证据边界；没有直接消融时写“证据链未闭环”，不要硬填实验结果。

若没有可独立成立的创新，不得硬凑，改用一个说明性 callout；有创新条目时不能用此声明跳过逐条校验：

```markdown
> [!example] 未识别到可独立成立的 Novelty
> 当前方案更接近已有组件的工程组合；说明其增量价值、原文依据及尚缺少的创新性对照。
```

以上仅示范排版，不是对具体论文的事实断言。最终报告用已核实的内容替换示例。

### 5. Potential flaw

依次回答：

1. 当前问题情境的维度、条件、约束、环境或任务覆盖有什么局限，架构延伸后可进入哪些新情境；
2. 在当前情境下，噪声、偏差、长尾、缺失、非平稳、相关性、标签错误、分布偏移或对抗性等坏数据性质会造成什么特有困难；
3. 哪个困难最值得发展成论文，并按影响面、严重性、可检验性和解法非平凡性说明理由。

### 6. Motivation

用一条或多条问句重建最自然的 idea 生成路径，典型形式为“之前的方法因为基本约束 X 而必须做 Y，那可不可以利用事实 Z，改为 W？”。从问题本质推到最小可行变化，不要从最终架构倒推一串不真实的灵感故事。

这里只保留简短的研究动机；完整的证据、设计和验证分支写在 §1.1 的研究逻辑链，并从这里回指。不要把重建的论证顺序写成作者实际产生想法或开展研究的时间顺序。

## 版式约束

- 本速览内部不使用任何形式的 LaTeX，也不使用美元符号数学定界符；公式和变量关系一律写成普通文本。
- 深度报告的后续章节仍按公式规范使用 LaTeX，本限制只作用于 `## 0. 第一性原理论文速览`。
- 保留 `Task`、`Challenge`、`Insight`、`Novelty`、`Potential flaw`、`Motivation` 标签，正文解释使用中文。

- 每条 Insight / Novelty 一个 callout，短标题不塞证据或长解释；只加粗字段名，不给整段加粗。
- 所有正文行保留 `> ` 前缀，每个字段之间必须留一个写为 `>` 的块内空行，确保渲染为独立段落，避免软换行重新挤成一段；相邻 callout 之间留一个真正的空行，防止合并。
- 默认展开，不嵌套 callout，不依赖额外 CSS；保持两种固定类型，不为凑数量拆分条目。
