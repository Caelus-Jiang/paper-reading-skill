# 研究逻辑链

让读者在进入公式前，看懂作者为什么选择这个方案，以及后面的每组实验、证明或协议在检验哪一步。这是报告的固定检查项；呈现长度随论文复杂度调整。

## 位置与粒度

- 在 §1.1 背景与动机后、§1.2 问题设定及详细公式前写入 canonical schema 的 `research_logic.heading`，不重编号既有章节。
- 至少写一段可独立理解的主线。存在会影响理解的分支时增加 Mermaid 图；复杂论文可再加“阶段—问题—证据—后续设计”表。简单论文用正文即可，不强制图表或固定节点数量。
- §0.6 只简述研究动机并回指主线。后续方法、证据章节通过过渡句说明正在解释或检验哪一步，不重复整段主线。

## 重建论证，而非猜测研究时间线

从原文中识别适用的连接：核心问题 → 原有假设或瓶颈 → 关键观察或推导 → 设计选择 → 验证证据 → 适用边界或未闭合环节。缺少或不适用的环节如实说明，不补造“先发现问题、再得到灵感”的故事。

优先依据作者明确给出的动机和章节证据；作者未明说的连接标记为 `reviewer 推断`，附原文位置。论文的章节顺序、报告的阅读顺序与研究实际开展顺序分别理解，不把它们混为一谈。

按主类型调整主线：

| 论文类型 | 优先连接的对象 |
| --- | --- |
| 方法 | 瓶颈、观察、设计、机制及效果验证 |
| 理论 | 问题、假设、关键引理、中心结论、证明依赖及反例 |
| 系统 / 数据集 / benchmark | 需求、约束、接口或协议选择、覆盖与泄漏检查、系统测试及边界 |
| 实证 | 待解释现象、竞争解释、对照、统计证据与外推范围 |
| 单篇综述 / 观点 | 核心问题、选材范围、综合依据、论证与竞争解释 |

## 标明连接的含义

区分三种关系：

1. **证据支持判断**：观察、推导或对照支持了什么，支持到什么强度？
2. **判断启发设计**：为何尝试该设计？不能把设计动机写成唯一性证明或有效性证明。
3. **证据检验设计**：实验、证明或测试究竟验证前提、代理模型、模块、机制，还是完整系统？

图中按实际含义标注“支持”“启发”“提供实验条件”“检验”等边。不同分支分别标明证据来源与验证对象，不能把一个代理模型更可信直接当成最终学习算法有效。所有连接应能回到原文章节、图表、定理、协议、代码或已有主张 ID；必要位置保留“证据链未闭环”。

例如，一篇论文可能从行为观察同时引出“监督者建模”和“学习方法设计”两条线：前者通过行为预测验证，并为后者提供仿真条件；后者还需独立的方法效果与机制证据。此例用于说明分支关系，不要求其他论文沿用其内容或时间顺序。

## 交付检查

- 主线能连接问题、核心判断、方案及决定性证据，术语与正文一致。
- 观察、作者解释、建模假设和 reviewer 推断分清；不以相关性替代因果性。
- 训练 / 推理、分析工具 / 学习模块、代理验证 / 方法验证等易混角色已区分。
- 方法和证据章节能接回主线，明确每个设计及验证对象；适用时在证据表增加研究阶段或验证对象列。
- 存在重要分支时不硬压成直线；关键连接缺证据时不补造结论。
- 结构验收只检查小节位置、唯一性与非空正文，不能判定论证是否正确，不把字数、关键词或箭头数量当作逻辑质量。
